# Contributing

This repository is always open for contributions, usually through [pull requests](https://docs.github.com/en/pull-requests/reference/pull-requests) as described below.

## How to Contribute

The process to contribute is as follows:

1. Fork (if allowed) or clone the repository.
2. Create a new branch for your changes.
3. Make your changes 
4. Test your changes
5. Commit your changes after testing
6. Push your changes to your fork or branch.
7. Submit a pull request.

## Naming Conventions

We follow some simple naming conventions for both branches and commits.

### Branch Naming

Branch names should be descriptive and follow the format `feat/description` or `bugfix/description`, where type can be any of the following:

- `feat`: A new feature or enhancement.
- `bugfix`: A bug fix.
- `hotfix`: A hotfix.
- `refactor`: A refactoring of existing code.
- `docs`: Documentation changes.
- `test`: Test changes.
- `chore`: Chore changes.

Descriptions should be concise and descriptive, using the imperative mood in kebab-case. Good examples include `feat/add-new-pipeline`, `bugfix/fix-duplicate-map` or `refactor/cleanup-code`.

### Commit Naming

For commit naming, we follow the [Conventional Commits](https://www.conventionalcommits.org/en/v1.0.0/) specification, which is a fairly standard and well established way to name commits. 

In the same mood as the given examples, good commit names include `feat: add new pipeline`, `fix: fix duplicate map` or `refactor: cleanup code`.
